# 合成用户访谈记录

> **重要**：以下访谈为作品集 Demo 编写的合成材料，用于练习“访谈 → 洞察 → 机会点”的产品方法。不是真实客户访谈，不得作为真实调研结果引用。

## 1. 访谈设计

- 目标：理解环保设备租赁从线索到退租的流程，找出高频、重复、可自动化的节点。
- 对象：8 位合成角色，覆盖运营、客服、交付、财务、市场、技术、销售、管理层。
- 方法：半结构化访谈，每人 30—40 分钟，追问“最近一次具体发生了什么”。
- 输出：流程节点、耗时、频率、痛点、现有工具、自动化意愿、风险。

## 3. 关键洞察

### 洞察 1：重复咨询集中在 5 类问题

- 押金、运费、安装、维保、发票。
- 新人培训周期长，答案版本不统一。
- 机会：FAQ RAG + 引用 + 低分转人工。

### 洞察 2：报价不是“查价格”，而是“多条件计算 + 审批”

- 设备、数量、天数、距离、折扣、税费、押金，任何一个变了都要重算。
- 机会：报价工具 + 参数校验 + 报价单模板；不要让 LLM 算。

### 洞察 3：订单进度分散在物流、交付、财务

- 客户问“到哪了”，客服要问三个人。
- 机会：订单状态工具 + 统一节点字典 + 主动通知。

### 洞察 4：内容生产和线索归因脱节

- 市场看阅读量，销售看线索，两边口径不一致。
- 机会：统一 UTM/CTA + 渠道/选题/线索报表 + 周复盘。

### 洞察 5：退租结算是最容易出错的节点

- 押金、损坏、耗材、逾期、发票跨部门。
- 机会：退租检查清单 + 自动对账 + 异常升级；高风险，先辅助不自动。

### 洞察 6：流程自动化要先排优先级

- 不是所有节点都值得做；高风险节点即使工时高，也要先人工复核。
- 机会：工时 × 潜力 × 数据就绪度 / 风险的机会矩阵。

## 4. 痛点 → 机会点

| 痛点 | 频率 | 影响 | 机会点 | 风险 |
| --- | --- | --- | --- | --- |
| 重复咨询 | 高 | 客服耗时、回答不一致 | FAQ RAG + 转人工 | 低 |
| 报价反复改 | 高 | 成交慢、易出错 | 报价工具 + 审批 | 中 |
| 订单进度分散 | 高 | 客户体验差 | 订单查询 + 通知 | 低 |
| 退租结算对账 | 中 | 押金纠纷 | 检查清单 + 对账 | 高 |
| 内容生产慢 | 中 | 线索少 | 内容 Workflow | 低 |
| 数据口径不一致 | 高 | 决策失真 | 指标字典 + 报表 | 中 |
| 投标读文件 | 中 | 漏条款、耗时 | 摘要 + 检查清单 | 中 |
| 流程优先级不清 | 高 | 资源浪费 | 机会矩阵 | 低 |

## 5. 访谈问题清单（可复用）

1. 你最近一次处理这个流程是什么时候？能按时间顺序讲一遍吗？
2. 哪一步最耗时？为什么？
3. 哪一步最容易出错？出错后果是什么？
4. 你现在用什么工具？Excel、微信、企微、邮件还是系统？
5. 如果只能自动化一步，你选哪一步？为什么？
6. 哪些环节绝对不能自动？为什么？
7. 你希望 AI 给你“答案”还是“草稿 + 依据”？
8. 你如何判断这件事做得好不好？有数据吗？
9. 如果 AI 错了，你希望怎么发现、怎么补救？
10. 谁使用、谁审核、谁负责？

## 6. 访谈方法的反思

- 不要问“你想不想要 AI”，要问“最近一次具体怎么做”。
- 不要只访管理层，要访一线执行者。
- 不要只记痛点，要记频率、耗时、错误成本。
- 不要把“用户说想要”当成需求，要看现有替代方案和行为。
- 合成访谈只能练习方法，不能替代真实调研。
