# 评测方法与失败分析

## 1. 为什么先做评测

AI 产品最容易犯的错误，是“Demo 看起来不错”就上线。这个仓库把评测放在实现之前：

- 先定义 60 条用例：50 条 FAQ + 10 条工具/转人工。
- 再定义指标：检索 Hit@k、MRR、意图准确率、工具准确率、引用命中率、转人工准确率。
- 最后用报告暴露失败案例，而不是只展示成功案例。

## 2. 评测集设计

| 子集 | 数量 | 目的 |
| --- | ---: | --- |
| 简单 FAQ 同义改写 | 40 | 验证基础召回；问法与知识库共享关键词 |
| 困难 FAQ 口语化问法 | 10 | 验证同义词泛化；刻意避开关键词 |
| 工具/转人工 | 10 | 验证报价、订单、投诉路由 |

困难问法示例：

- “开票要几个点？” → 期望 `tax`，但知识库写的是“发票 / 税率”。
- “机器坏了，师傅多久能到？” → 期望 `maintenance`，但知识库写的是“故障 / 维保 / 响应”。
- “设备被偷了怎么办？” → 期望 `insurance`，但知识库写的是“损坏 / 丢失 / 保险”。
- “晚还几天怎么算钱？” → 期望 `penalty`，但知识库写的是“逾期 / 违约金”。

## 3. 指标口径

### 检索

- **Hit@1**：Top1 文档的 `group_id` 是否命中期望组。
- **Hit@3**：Top3 文档中是否有命中。
- **MRR**：第一个命中结果的倒数排名均值。
- 按 `group_id` 去重，避免同一知识点的 7 种问法占据 Top3。

### Agent

- **意图准确率**：FAQ / 报价 / 订单 / 转人工是否分类正确。
- **工具准确率**：期望工具是否出现在 `tool_calls` 中。
- **引用命中率**：回答的 `citations` 是否包含期望知识点。
- **转人工准确率**：期望转人工的用例是否真的创建了工单。

### 基线

关键词基线使用字符 token 的重合度排序（不做 BM25 长度归一化），用于回答“BM25 到底有没有用”。

## 5. 失败分析

### 失败 1：开票 → 发票

- 用户问：“开票要几个点？”
- 期望：`tax`
- 实际 Top1：`invoice`

原因：`开票` 和 `发票` 是同一业务动作的不同说法，但字符 bigram 没有重叠。  
修复：增加业务同义词词典（开票→发票/税率），或在检索前做 query expansion。

### 失败 2：师傅 → 维保

- 用户问：“机器坏了，师傅多久能到？”
- 期望：`maintenance`
- 实际 Top1：`delivery`

原因：`师傅` 不在知识库，`多久能到` 与“发货/到货”更相似。  
修复：增加“师傅→工程师/维保/到场”的同义词，同时把“响应时间”作为结构化字段，而不是只放在长答案里。

### 失败 3：被偷 → 保险

- 用户问：“设备被偷了怎么办？”
- 期望：`insurance`
- 实际 Top1：`capacity`

原因：`被偷` 没有出现在知识库，模型只能抓到“设备”这种泛词。  
修复：增加“被偷/丢失/损坏→保险/赔偿”的同义词；在意图路由中增加“财产损失”子意图。

### 失败 4：晚还 → 逾期

- 用户问：“晚还几天怎么算钱？”
- 期望：`penalty`
- 实际 Top1：`capacity`

原因：`晚还` 与“逾期/违约金”没有字符重叠。  
修复：同义词扩展 + 把“逾期计费”做成独立 FAQ，而不是只放在退租答案里。

## 6. 为什么不用 100% 作为目标

- 100% 很可能意味着评测集太简单，或者知识库和评测集共享了太多词。
- 真实用户会使用口语、省略、错别字、方言和上下文指代。
- 产品上更重要的是：**错了能不能被发现、能不能转人工、能不能快速修**。

因此本仓库保留 4 条困难失败案例，并在报告中标注，而不是通过扩大关键词匹配把数字“调”到 100%。

## 7. 下一步

1. **Query expansion**：业务同义词词典 + 用户日志回流。
2. **混合检索**：BM25 + embedding，比较不同问法的召回。
3. **Rerank**：对 Top10 做 cross-encoder 或 LLM rerank。
4. **多轮对话**：槽位继承、指代消解、上下文澄清。
5. **真实 LLM 评测**：同一套用例对比模板 Writer 与 GPT/Claude 的事实性、引用率、语气和成本。
6. **线上指标**：转人工率、一次解决率、用户满意度、P95 延迟、单次成本。

## 8. 复现

```bash
python -m ai_portfolio.cli eval
```

输出：

- `reports/eval_results.json`：机器可读的逐条结果。
- `reports/eval_report.md`：人类可读的指标、失败案例、口径说明。
